# 异常处理使用指南

## 概述

本文档介绍如何使用 CaseManager 系统的统一异常处理机制。该机制包括：

- **BusinessException** - 统一的业务异常类
- **BusinessErrorCode** - 业务错误码枚举
- **GlobalExceptionHandler** - 全局异常处理器
- **ExceptionUtil** - 异常工具类

## 错误码规范

错误码按模块划分，每个模块分配特定的错误码范围：

- **10000-19999**：通用错误
- **20000-29999**：用户相关错误
- **30000-39999**：项目相关错误
- **40000-49999**：测试用例相关错误
- **50000-59999**：测试计划相关错误
- **60000-69999**：缺陷相关错误
- **70000-79999**：报告相关错误
- **80000-89999**：系统相关错误
- **90000-99999**：其他错误

## 使用示例

### 1. 直接抛出业务异常

```java
import com.casemanager.common.exception.BusinessException;
import com.casemanager.common.enums.BusinessErrorCode;

// 使用预定义的错误码
throw new BusinessException(BusinessErrorCode.USER_NOT_FOUND);

// 使用预定义的错误码，自定义错误信息
throw new BusinessException(BusinessErrorCode.USER_NOT_FOUND, "用户ID: " + userId + " 不存在");

// 直接指定错误码和信息
throw new BusinessException(20001, "用户不存在");

// 只指定错误信息（默认错误码为500）
throw new BusinessException("操作失败");
```

### 2. 使用异常工具类

```java
import com.casemanager.common.exception.ExceptionUtil;
import com.casemanager.common.enums.BusinessErrorCode;

// 抛出参数错误
ExceptionUtil.throwParamError();
ExceptionUtil.throwParamError("用户名不能为空");

// 抛出数据不存在异常
ExceptionUtil.throwDataNotFound();
ExceptionUtil.throwDataNotFound("项目不存在");

// 抛出权限不足异常
ExceptionUtil.throwPermissionDenied();
ExceptionUtil.throwPermissionDenied("您没有权限访问该项目");

// 使用断言方法
ExceptionUtil.assertNotNull(user, BusinessErrorCode.USER_NOT_FOUND);
ExceptionUtil.assertTrue(user.isActive(), BusinessErrorCode.USER_DISABLED);
ExceptionUtil.assertFalse(project.isDeleted(), BusinessErrorCode.PROJECT_DELETED);
```

### 3. 在 Service 层使用

```java
@Service
public class UserService {
    
    @Autowired
    private UserRepository userRepository;
    
    public User getUserById(Long userId) {
        User user = userRepository.findById(userId).orElse(null);
        
        // 使用异常工具类
        ExceptionUtil.assertNotNull(user, BusinessErrorCode.USER_NOT_FOUND, 
            "用户ID: " + userId + " 不存在");
        
        // 检查用户状态
        if (!user.isActive()) {
            throw new BusinessException(BusinessErrorCode.USER_DISABLED);
        }
        
        return user;
    }
    
    public void updatePassword(Long userId, String oldPassword, String newPassword) {
        User user = getUserById(userId);
        
        // 验证原密码
        if (!passwordEncoder.matches(oldPassword, user.getPassword())) {
            throw new BusinessException(BusinessErrorCode.USER_OLD_PASSWORD_ERROR);
        }
        
        // 验证新密码不能与原密码相同
        if (oldPassword.equals(newPassword)) {
            throw new BusinessException(BusinessErrorCode.USER_PASSWORD_SAME);
        }
        
        user.setPassword(passwordEncoder.encode(newPassword));
        userRepository.save(user);
    }
}
```

### 4. 在 Controller 层使用

```java
@RestController
@RequestMapping("/api/users")
public class UserController {
    
    @Autowired
    private UserService userService;
    
    @GetMapping("/{id}")
    public ApiResponse<User> getUser(@PathVariable Long id) {
        // 参数验证
        if (id == null || id <= 0) {
            ExceptionUtil.throwParamError("用户ID无效");
        }
        
        User user = userService.getUserById(id);
        return ApiResponse.success(user);
    }
    
    @PostMapping("/register")
    public ApiResponse<User> register(@RequestBody @Valid UserRegisterDTO dto) {
        // 检查用户是否已存在
        if (userService.existsByUsername(dto.getUsername())) {
            throw new BusinessException(BusinessErrorCode.USER_ALREADY_EXISTS, 
                "用户名已被使用: " + dto.getUsername());
        }
        
        if (userService.existsByEmail(dto.getEmail())) {
            throw new BusinessException(BusinessErrorCode.USER_EMAIL_EXISTS);
        }
        
        User user = userService.register(dto);
        return ApiResponse.success(user);
    }
}
```

### 5. 自定义业务异常

如果需要添加新的错误码，可以在 `BusinessErrorCode` 枚举中添加：

```java
public enum BusinessErrorCode implements IErrorCode {
    // ... 现有错误码 ...
    
    // 添加新的错误码
    USER_VERIFICATION_CODE_ERROR(20016, "验证码错误"),
    USER_VERIFICATION_CODE_EXPIRED(20017, "验证码已过期"),
    
    // ... 其他错误码 ...
}
```

### 6. 全局异常处理

`GlobalExceptionHandler` 会自动捕获并处理所有异常，返回统一的响应格式：

```json
{
    "code": 20001,
    "message": "用户不存在",
    "data": null,
    "success": false
}
```

支持的异常类型：
- 业务异常 (BusinessException)
- 参数校验异常 (MethodArgumentNotValidException, BindException, ConstraintViolationException)
- 请求参数异常 (MissingServletRequestParameterException, MethodArgumentTypeMismatchException)
- HTTP异常 (HttpRequestMethodNotSupportedException, HttpMediaTypeNotSupportedException)
- 系统异常 (NullPointerException, RuntimeException, Exception)

## 最佳实践

1. **优先使用预定义的错误码**：使用 `BusinessErrorCode` 中定义的错误码，保持错误信息的一致性。

2. **提供有意义的错误信息**：在抛出异常时，尽量提供详细的错误信息，帮助定位问题。

3. **使用异常工具类**：使用 `ExceptionUtil` 提供的便捷方法，减少代码重复。

4. **在 Service 层处理业务逻辑异常**：将业务逻辑相关的异常处理放在 Service 层。

5. **在 Controller 层处理参数验证**：使用 `@Valid` 注解和异常工具类进行参数验证。

6. **不要捕获业务异常**：让业务异常向上传播，由全局异常处理器统一处理。

## 注意事项

1. `GlobalExceptionHandler` 使用了 `@RestControllerAdvice` 注解，会自动处理所有 Controller 抛出的异常。

2. 异常处理器使用了 Jakarta EE 的包（jakarta.servlet, jakarta.validation），适用于 Spring Boot 3.x。如果使用 Spring Boot 2.x，需要将 jakarta 改为 javax。

3. 所有的业务异常都会返回 HTTP 200 状态码，通过响应体中的 code 字段区分错误类型。

4. 系统异常（如空指针异常、运行时异常）会返回 HTTP 500 状态码。

5. 参数验证失败会返回 HTTP 400 状态码。
